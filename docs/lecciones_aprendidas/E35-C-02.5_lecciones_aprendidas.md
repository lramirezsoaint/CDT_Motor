# E35-C-02.5 lecciones aprendidas

- Para duplicidad en `Configuración de Parches`, conviene tomar la primera fila simple y repetir solo la combinación base que la UI deja reconstruir con estabilidad.
- Forzar todos los campos opcionales del parche vuelve el caso frágil; para negocio es más robusto repetir `Atribuible`, `Tipo de Gasto`, `GA/GM`, `UOA Antes`, `UOA Después` y `Porcentaje`.
- El flujo quedó estable cuando se evitó reconstruir campos opcionales inestables como `Ramo`, `Producto` o `Subcanal` si la propia fila base no los necesitaba para disparar el duplicado.
