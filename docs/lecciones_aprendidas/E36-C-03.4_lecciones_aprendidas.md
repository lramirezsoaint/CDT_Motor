# E36-C-03.4 - Lecciones Aprendidas

## Objetivo

Documentar los hallazgos al implementar `E36-C-03.4`, enfocado en validaciones negativas por campo dentro de `Comunes > Subcanales`.

## Hallazgos

- El caso mezcla dos tipos de validación:
  - obligatoriedad de `Código Canal`
  - formato inválido de `Nombre Subcanal`
- `Código Canal` es un combo, por lo que no puede tratarse como si fuera un textbox normal.
- En estos casos hay que distinguir entre campo visible, campo editable y campo realmente vaciable.

## Decisiones tomadas

- Se validó obligatoriedad de `Nombre Subcanal` y `Código Canal` solo si la UI permite vaciarlos.
- Si un campo no pudo vaciarse, el test dejó anotación en vez de generar un falso bug.
- Se validó formato inválido sobre `Nombre Subcanal` con caracteres especiales.

## Patrones reutilizables

- En combos obligatorios, primero intentar vaciarlos por la propia UI; si no se puede, dejar trazabilidad y no forzar el caso.
- En campos textuales, la validación de formato debe seguir el mismo patrón que en `Líneas` y `Canales`.
- El helper compartido de edición negativa reduce mucho la duplicación entre entidades de `Comunes`.

## Recomendaciones

- Seguir este mismo patrón para otros modales con relación entre un campo textual y un campo combo obligatorio.
- No asumir que todos los combos obligatorios pueden volver a estado vacío.
