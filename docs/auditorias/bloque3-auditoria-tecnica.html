6. Reutilización y Duplicidad

  • Los flujos de carga están bien centralizados en gf-upload.ts y gf-upload-case.ts.
  • Los specs E9-GF-* repiten la misma validación de tabla, cabeceras, filas y primera celda.
  • Los helpers de descarga y columnas repiten login manual antes de ensureGfContext.
  • Hay lógica de navegación local que podría reutilizar _globalshared/navigation/sidebar.ts.
  • La descarga simple podría reutilizar _globalshared/download/download-assertions.ts.
  • El upload local de GF podría alinearse con _globalshared/upload/upload-flow.ts para reducir duplicidad transversal.

12. Tags

  • @bloque3 aparece en títulos generados por helpers y en specs directos principales.
  • Algunos specs parametrizados no contienen tags literales en el archivo porque se generan mediante buildTags.
  • Flow tags detectados: @login, @distribucion, @upload_valido, @upload_invalido, @download_catalogo, @columnas, @busqueda, @paginacion.
  • No hay uso sistemático visible de @critical o @regression en todos los casos de alto valor.

13. Imports

  • Se detecta dependencia cruzada riesgosa en pages/distribucion/DistribucionPage.ts: importa ensureAmContext desde tests/e2e/bloque-5/_shared/am-context.
  • Helpers de columnas y descarga importan env y LoginPage para login manual, aunque después usan contexto GF.
  • No se observaron ciclos evidentes en Bloque 3, pero sí acoplamiento entre pages y helpers específicos de tests.
  • La auditoría fue estática; no se ejecutó compilación para confirmar imports sin usar con TypeScript.

17. Riesgos

  • Falsos positivos por skips suaves en descargas.
  • Falsos fallos por specs Admin corriendo bajo proyecto GF.
  • Fallas ambientales por distribución y periodo hardcodeados.
  • Fragilidad por XPath, nth(), networkidle y waitForTimeout.
  • Catálogo JSON no confiable para planeación de cobertura.
  • Dependencia cruzada Bloque 3/Bloque 5 en Page Object compartido.
  • Falta de tags sistemáticos para criticidad/regresión.

18. Recomendaciones

Cambios críticos

  • Sanear la fuente de catálogo: decidir Markdown o JSON como fuente oficial y corregir contaminación AM/GF.
  • Separar specs Admin o ajustar configuración para que corran bajo chromium.
  • Eliminar la dependencia de ensureAmContext desde DistribucionPage.
  • Convertir skips suaves de descarga en bloqueo explícito de datos o fallo controlado.

Cambios recomendados

  • Extraer helper para validación de tablas de E9-GF-*.
  • Reutilizar global shared para navegación, downloads y flujos genéricos de upload.
  • Parametrizar periodo/distribución en gf-context.ts.
  • Reducir waitForTimeout, networkidle, XPath y nth().

Mejoras futuras

  • Agregar reporte automático de cobertura catálogo vs specs.
  • Normalizar tags @critical, @regression, @upload, @download, @columnas y @distribucion.
  • Crear matriz viva de casos pendientes con razón y dependencia de datos.

Optimizaciones

  • Reducir timeouts altos mediante esperas web-first más específicas.
  • Consolidar login manual y storage state en un único patrón por rol.
  • Crear factories de descarga y columnas con validaciones por entidad.
